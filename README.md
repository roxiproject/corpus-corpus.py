## corpus-corpus: a from-scratch numpy training harness

Everything below this line was added later, on top of the placeholder
content above (which is left untouched). This is a real, working,
numpy-only neural network training harness — no torch, jax, or
tensorflow anywhere in the dependency graph.

### Architecture overview

- `corpus_corpus/activations.py` — ReLU and GELU (tanh-approximation),
  each with a hand-derived analytic backward pass.
- `corpus_corpus/losses.py` — numerically stable softmax + cross-entropy
  with a hand-derived combined gradient (`softmax(logits) - one_hot`,
  batch-averaged).
- `corpus_corpus/mlp.py` — `Dense` layer and `MLP` stack. Backprop is
  written out by hand (no autodiff engine): each `Dense.backward` composes
  the local Jacobians of `y = xW + b` and the activation via the chain
  rule.
- `corpus_corpus/optim.py` — `SGD` (classical momentum) and `Adam` (with
  correct bias-corrected first/second moment estimates), operating on
  raw numpy arrays in place.
- `corpus_corpus/data.py` — minibatching with per-epoch shuffling (seeded,
  deterministic given an `np.random.Generator`), and a train/val split.
- `corpus_corpus/schedule.py` — linear warmup and cosine decay LR
  schedules, composable as `warmup_then_cosine`.
- `corpus_corpus/checkpoint.py` — save/load MLP weights to/from `.npz`.
- `corpus_corpus/metrics.py` — per-epoch CSV/JSONL metrics logging plus
  a `build_report` / `report_from_file` summary (final metrics, best
  epoch by val loss).
- `corpus_corpus/toy_data.py` — two toy classification tasks used to
  prove the harness actually trains something: XOR, and a two-spirals
  task built from real trigonometric geometry (not random labels).
- `corpus_corpus/train.py` — the training loop: minibatch + shuffle each
  epoch, LR scheduling per step, early stopping with patience (on val
  loss), checkpointing the best-so-far weights.
- `corpus_corpus/config.py` — JSON and YAML (via PyYAML, since it was
  already available in this environment; JSON always works with no extra
  dependency) config loading with sensible defaults.
- `corpus-corpus.py` — the CLI entry point (argparse-based):
  `train`, `eval`, and `report` subcommands.

### Running it

```bash
python3 corpus-corpus.py train --config config.json
python3 corpus-corpus.py eval  --checkpoint model.npz --config config.json
python3 corpus-corpus.py report --metrics metrics.csv
```

`config.json` in the repo root is a working example config for the XOR
toy task.

### The toy task and real measured accuracy

Two toy tasks are included:

1. **XOR** — the classic non-linearly-separable problem, jittered with
   Gaussian noise around the four corners so there's more than 4 points
   to train/validate on.
2. **Two spirals** — a harder 2D toy task built from real spiral
   geometry (`radius, angle` parametrized by `t`), not randomly assigned
   labels.

Measured results from an actual run of `python3 corpus-corpus.py train
--config config.json` (XOR, MLP `[2, 16, 16, 2]`, Adam, cosine LR decay
with linear warmup, 300 epochs, early stopping patience 30):

```
final val_loss=0.0000 val_acc=1.0000
best epoch=299 best_val_loss=8.597e-07 best_val_acc=1.0000
```

The harder two-spirals toy task (MLP `[2, 32, 32, 2]`, 400 epochs) also
reaches `val_acc=1.0000` (`val_loss≈0.0036` at its best epoch). These are
real numbers from real runs of the code in this repo, not fabricated —
reproduce them yourself with the commands above.

### Gradient checking

Backprop through the whole MLP (dense layers + ReLU/GELU + softmax
cross-entropy) is verified against central-difference numerical
gradients (`tests/gradcheck_utils.py`, `eps=1e-5`) in
`tests/test_gradcheck_mlp.py`, `tests/test_activations.py`, and
`tests/test_losses.py`. This covers:

- 6 different `(layer_sizes, activations)` configurations, including
  ReLU-only, GELU-only, and mixed-activation networks up to 5 hidden
  layers deep, checking gradients on every `W` and `b` in every layer.
- Gradient w.r.t. the network's *input* (chain rule all the way through).
- Per-activation gradient checks for ReLU and GELU in isolation.
- The softmax cross-entropy gradient in isolation.

All gradient checks pass with a relative error tolerance of `1e-4`–`1e-6`
depending on the check (looser tolerance for deeper compositions, since
numerical error compounds).

## Related projects

in a small corpus pipeline in the
[roxiproject](https://github.com/roxiproject/roxiproject) account:
`corpus-kit` builds/cleans → `corpus-corpus.py` dedupes/filters by language
→ `corpus-tokenizer-kit` tokenizes → `corpus-bench` benchmarks the result.

- [corpus-bench](https://github.com/roxiproject/corpus-bench) — benchmarks corpus-processing throughput/quality across the pipeline.
